# Benchmark

Measure raywarp on your GPU: frame time, images per second, first-frame time and compile count of
one scene.

> **New in 0.4.0:** the public benchmark script, `benchmarks/run.py`.

## Quick start

From a checkout's root:

```bash
python -m benchmarks.run --scene franka --worlds 64 --res 512
python -m benchmarks.run --scene franka --worlds 64 --res 512   # again: the warm first frame
```

The scene downloads on first use. The script prints its numbers and saves one PNG.

## Options

| option | default | what |
| --- | --- | --- |
| `--scene franka\|showcase\|sponza` | required | MuJoCo Menagerie's Franka, raywarp's showcase room, Intel's New Sponza |
| `--worlds N` | 64 | worlds per frame, one camera each |
| `--res R` | 512 | square image side in pixels |
| `--settings default\|fast` | `default` | `rw.RenderSettings()`, or `rw.FAST` over it |
| `--frames N` | 100 | timed frames |
| `--device D` | `cuda` | the Warp device |
| `--png PATH` | `benchmark-<scene>.png` | the saved image |

[benchmarks/README.md](../benchmarks/README.md) explains each number, the scenes' sources and
their licences.

## Comparison with other batch renderers

One job on one GPU (an RTX PRO 6000 Blackwell) times raywarp and the batch renderers robot-learning
stacks ship with, on the same machine, warm, in turn. The results JSON is
`benchmarks/results/compare.json`; `python benchmarks/compare_table.py benchmarks/results/compare.json`
prints the tables below (`--bars`: the records of the bar charts).

### What is measured

- **Matrix.** Scenes: `franka` (MJCF); `g1_usd`, Newton with USD: Newton's Unitree G1 loaded
  from its USD stage (`ModelBuilder.add_usd`, 29 dof + hands, visual meshes) with three props,
  `replicate`d to N worlds on a ground plane, joint angles varied per world, the state stepped by
  Newton's MuJoCo solver (`SolverMuJoCo`) before timing, one third-person camera
  per world and Newton's default light direction for every renderer; `showcase` and `sponza`
  (raywarp's scene files: no other renderer here loads them, so they are raywarp-only rows). Square images of 128, 512 and 1024 px;
  1, 64 and 512 worlds (and 1024 worlds at 128 px); one camera per world; outputs RGB, and RGB +
  depth.
- **One call** renders every world's camera from a fixed simulator state; each renderer does its
  full per-frame work in that call (raywarp and MuJoCo Warp refit their BVH, Newton refits its
  shapes, ManiSkill updates its render bodies and reads its textures back as tensors, Genesis
  updates its poses). Physics stepping is outside every timed window.
- **Timing.** 2 warm-up calls, then the median of 3 intervals of about 0.6 s with a device
  synchronize at each end. images/s = worlds x 1000 / (ms per call).
- **Warm.** Every renderer runs once untimed before its rows (kernels compiled or downloaded, shader
  caches filled). raywarp's rows record the kernels compiled inside the timed window: 0 (the
  prebuilt kernels of the GPU's architecture).
- **First frame:** the process's first renderer, from its construction to its first image on the
  device (warm disk caches); **startup:** from the process's launch (interpreter, imports, scene
  load) to that image.
- **Peak GPU memory:** device memory in use at the row's peak minus the idle device: CUDA / Vulkan
  context, scene, renderer and outputs.
- **Quality:** Mitsuba 3 path-traces the franka scene at 512 px (1024 spp, 6 bounces, raywarp's
  BRDF, lights and exposure: the same inputs), shown through the same display transform; the table
  gives the mean FLIP of each 512 px image against it (lower is closer). Only renderers that render
  the same MJCF under the same lights get a FLIP; the others rebuild or relight the scene, so their
  difference would not be the renderer's.

### What each renderer computes

The numbers are only comparable with this in mind: a rasteriser with shadow maps and a ray tracer
with GI do different amounts of work per pixel.

| Renderer | Kind | Lighting and shadows | GI, reflections | AA | Scene in this benchmark |
|---|---|---|---|---|---|
| Raywarp default | ray tracer, OptiX on RT cores | OpenPBR materials; the MJCF lights; area lights through LTC; ray-traced hard shadows, up to 4 casters per pixel | diffuse GI from irradiance probes (baked on the first frame, relit when lights change); mirror and glossy reflection rays | none (1 spp) | the scene files as published |
| Raywarp FAST (`rw.FAST`) | same | as default, area lights point-form, 2 shadow casters per pixel, no translucent shadows | GI probes; no reflection rays | none | same |
| Raywarp `fast@software` | ray tracer, Warp BVH on CUDA cores (the A100 / H100 path) | as FAST | as FAST | none | franka, a few sizes |
| MuJoCo Warp `shadows` | ray tracer, Warp BVH on CUDA cores | MuJoCo's Phong-style lighting of the MJCF lights, headlight ambient, textures; ray-traced hard shadows | none | none (`samples_per_pixel` 1) | the same franka MJCF |
| Raywarp `sensor-api` (g1_usd) | as default, OptiX | raywarp's drop-in for Newton's `SensorCamera` (`from raywarp.integrations.newton.sensor import SensorCamera`): Newton's calls and default light | as default | none | the Newton model |
| Newton `SensorCamera` | ray tracer, Warp BVH on CUDA cores | Lambert; Newton's default directional light (it reads no MJCF light); ray-traced hard shadows; textures | none | none | the same franka MJCF (`add_mjcf`); the Newton USD model |
| ManiSkill 3 / SAPIEN `minimal`, `default` | rasteriser (Vulkan), batched GPU render system | SAPIEN's shader packs (`minimal`: ManiSkill's camera default); shadow maps | none | none | rebuilt with ManiSkill's API: its own Panda, its ground, the MJCF's boxes, lights and camera |
| Madrona (Genesis `BatchRenderer`) `raytracer`, `rasterizer` | Madrona's ray tracer or rasteriser, CUDA | the MJCF's four lights added with `scene.add_light`, their shadows | none | none | the same robot MJCF; Genesis' plane and boxes |

Not in the table:

- **madrona-mjx** (MJX's Madrona renderer): no wheel; its source build needs CUDA <= 12.5 and
  jax < 0.6, which have no sm_120 (Blackwell) target. Madrona appears through Genesis'
  `gs-madrona` wheel instead.
- **Isaac Lab tiled camera**: needs Isaac Sim (`isaacsim` on PyPI: a ~15 GB install, the NVIDIA
  Omniverse EULA to accept, Kit's RTX shader compilation on first start), beyond one batch job.
- **Mitsuba 3** is the quality reference, not timed: it is an offline path tracer.
- **On the Newton + USD model**, the renderers a Newton user has are Newton's `SensorCamera`
  (batched) and raywarp. Newton's GL viewer renders one view (no batch); its RTX viewer goes
  through Omniverse RTX (`ovrtx`: minutes of shader compilation on first use), as does Isaac Lab;
  MuJoCo Warp, ManiSkill and Genesis do not load a Newton model or a USD physics stage.

### Clips

For the side-by-side montage, each renderer mode also renders a 6 s, 1280 x 720, 30 fps clip of
one world: on `franka`, the arm moving through the same joint path (`common.clip_qpos`) seen from
the benchmark camera; on `g1_usd`, the G1's joints driven by the same path. The job encodes them
(H.264) beside a still of their first frame; `compare.json`'s `clips` lists them with the
renderer, mode, the render time of a clip frame and the mode's images/s at 512 px x 512 worlds.

raywarp is the only renderer here with global illumination and reflections; the others render
direct light only. RGB + depth rows request both outputs from each renderer in the same call.
